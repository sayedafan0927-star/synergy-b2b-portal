# 🔌 Интеграционные Стандарты и Протокол Обмена с ERP (erp.synergy-tech.kz)

Данный документ описывает правила интеграции B2B-портала с корпоративной системой 1C:ERP (`erp.synergy-tech.kz/api_portal.php`), архитектуру вебхуков CDC (Change Data Capture), протокол бесшовного SSO и защиту от рассинхронизации.

---

## 1. Схема информационных потоков

```
┌─────────────────────────────────┐                 ┌─────────────────────────────────┐
│       Synergy B2B Portal        │                 │         Корпоративная ERP       │
│      (Vercel Serverless)        │                 │      (erp.synergy-tech.kz)      │
└────────────────┬────────────────┘                 └────────────────┬────────────────┘
                 │                                                   │
                 │ 1. Создание заказа (POST /api/erp)                │
                 ├──────────────────────────────────────────────────►│ (Таймаут 2.5с)
                 │    В случае таймаута: перенос в Outbox            │
                 │                                                   │
                 │ 2. Синхронизация Outbox (POST /api/outbox/sync)   │
                 ├──────────────────────────────────────────────────►│ (Повторные попытки)
                 │                                                   │
                 │ 3. CDC Вебхуки: Дельты остатков, статусы          │
                 │◄──────────────────────────────────────────────────┤ (POST /api/webhooks/erp)
                 │    (Проверка монотонного version_timestamp)       │
                 │                                                   │
                 │ 4. Вход сотрудника через SSO Magic Link           │
                 │◄──────────────────────────────────────────────────┤ (GET /api/auth/erp-sso)
                 │    (HMAC-SHA256 подпись + TTL 300 сек)            │
```

## 2. Защита от нарушения порядка вебхуков (Monotonic CDC Versioning)

При пиковых нагрузках на сеть вебхуки об изменении остатков на складе могут приходить не по порядку (сетевая гонка / out-of-order delivery).
- **Сценарий риска**: В 12:00:00 остаток стал 10 шт. В 12:00:05 остаток стал 3 шт. Вебхук за 12:00:05 пришел первым, а за 12:00:00 задержался и пришел вторым. Если применить его в лоб, актуальный остаток 3 шт. перезапишется устаревшим значением 10 шт.

### ✅ Обязательный стандарт монотонного версионирования:
1. Каждый вебхук остатков **обязан** содержать `version_timestamp` (Unix timestamp в миллисекундах или микросекундах).
2. Модуль кэша `catalogCache.ts` сравнивает версию:
```typescript
if (incomingVersionTimestamp <= currentCachedVersionTimestamp) {
  logger.warn('Stale CDC webhook discarded', {
    incoming: incomingVersionTimestamp,
    current: currentCachedVersionTimestamp
  });
  return res.status(200).json({ status: 'ignored_stale_version' });
}
```
* Устаревшие вебхуки отбрасываются, целостность остатков на портале гарантирована.

## 3. Гарантированная доставка заказов (Outbox & Retry Pattern)

Все заказы, которые не удалось мгновенно передать в ERP из-за сетевого сбоя или срабатывания Circuit Breaker:
1. **Сохраняются в статусе `pending`** с событием в таблице `outbox_events`.
2. **Фоновый процесс `api/outbox/sync.ts`**:
   - Выполняет опрос необработанных событий;
   - Применяет экспоненциальный откат (Exponential Backoff: 1с → 2с → 4с → 8с → 16с);
   - После 5 неудачных попыток заказ переводится в статус `failed_dlq` (Dead Letter Queue);
   - В инженерный канал Telegram и дежурному в WhatsApp немедленно уходит критический алерт с номером заказа, суммой и телом ошибки.

## 4. Безопасность SSO Magic Link (HMAC-SHA256)

Для перехода сотрудников из интерфейса ERP в B2B-портал без ввода логина и пароля используется криптографический протокол:

### 4.1. Формирование ссылки в ERP
URL: `https://b2b.synergy.kz/api/auth/erp-sso`
Параметры:
- `manager_id`: ID сотрудника в ERP;
- `role`: роль (`admin`, `manager_rm`, `manager_lm`, `client`);
- `name`: ФИО сотрудника;
- `phone`: телефон;
- `timestamp`: текущее время Unix timestamp (`time()`);
- `token`: криптографическая подпись:
  ```
  token = HMAC_SHA256("{manager_id}:{role}:{timestamp}", ERP_PORTAL_SECRET)
  ```

### 4.2. Правила валидации на портале (`api/auth/erp-sso.ts`):
- **Окно валидности (TTL)**: строго **300 секунд (5 минут)**. Ссылки старше 5 минут отклоняются со статусом 403 Forbidden.
- **Защита от Replay-атак**: использованный токен помечается в Redis, повторный переход по той же ссылке невозможен.
- **Исключение парольных обходов**: запрещено создание пользователей без проверки криптографической подписи.

## 5. Санитизация и маскирование PII в журналах аудита

Все входящие и исходящие вызовы ERP фиксируются в таблице `integration_audit_logs`.

### Правило маскирования (`api/audit/logs.ts`):
Любые чувствительные поля автоматически заменяются на `***MASKED***`:
- Пароли, токены, API-ключи (`api_key`, `token`, `password`, `secret`);
- Персональные телефоны и номера удостоверений/паспортов;
- Банковские реквизиты (IBAN, номера карт).
